# v0.1 implementation sequence (planned order; implementation evidence updated 2026-11-01)

**Rule:** document-first, then direct atomic commits to main; no feature branches, no E2E or release automation; add real unit tests alongside each code unit.

## Phase 0: D0 review
- Review PRD, endpoint event contract, policy/notice scope, initial Windows/Linux target, bootstrap CA and device-key approach.
- Resolve or intentionally record blockers in [open decisions](../governance/open-decisions.md).
- Complete **ARCH-01 protocol/schema fixture freeze before D0 approval**, together with D-07 Agent PKI decisions and the V0.1 role/group/privacy baseline. ARCH-01 is a documentation decision, not permission to create implementation code.
- No implementation code until maintainer approves D0. No real employee data before additional organizational approvals.

## Suggested small commit slices
- Define types and versioned envelope (docs / minimal shared contracts).
- Create PG migrations for admin/enrollment and unique device/event keys. Use [Gradle Groovy reference](../development/backend-gradle-reference.md) and Spring Boot BOM-managed Flyway PostgreSQL support.
- Unit test single-use token and wrong-device denial.
- Use SQLx SQLite migrations and one-connection write pool, then synthetic event uploader. No custom SQLite blocking worker.
- Expose separate `/inventory` snapshot endpoint + latest metrics, server heartbeat/event routes and role-scoped Dashboard Device Details. A full hardware/network snapshot is not sent at every heartbeat.
- Add **WSS status notifications** only after session/Origin/server-side device scope are checked; connect browser, fetch authorized device IDs, subscribe, then **take another REST snapshot after subscription acceptance**; repeat on reconnect.
- Integrate real Windows/Linux heartbeat (no screen capture yet). Test the user's reported Pop!_OS 24.04/KDE KWin machine first, recording the actual X11/Wayland session; Windows 11 requires a separate real machine.
- Complete two-device manual smoke and document outcomes.

## MVP v0.1 deliberately excludes
Applications/window timeline, Windows Sysmon integration, Linux auditd ingestion, recording/playback, WebRTC, remote command execution, installer auto-update, AI, microservices, Kafka, E2E and exhaustive CI. These belong to later specified milestones. **Maintainer amendment (2026-11-01):** Optional Spring Data Redis 8/Lettuce is now permitted solely for 90-second non-authoritative hints/health, reusing existing `spark-redis` (OFF by default). It is not a session store, device-status authority, distributed WSS broker, or event transport; PostgreSQL and SQLite continue to own durable state.

## Key milestone definition
A v0.1 demo must show **one Windows 11 + one selected Linux endpoint → authenticated server → PostgreSQL → Monitoring Center with hardware/OS/network inventory and WSS status push**, then survive an induced temporary LAN outage with replay and duplicates not duplicated. Browser WS reconnection refetches REST and does not leak cross-group status. If any step is missing, milestone remains incomplete.
