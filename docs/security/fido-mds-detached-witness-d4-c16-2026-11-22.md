# A11-D4-C16 — detached offline signed witness for the PostgreSQL V30 tail

**Date:** 2026-11-22 · **Branch:** `main` only · **New functional-source CI:** PENDING · **v0.1 NOT RELEASE READY.**

## Threat boundary: PostgreSQL-local history is not an independent witness

D4-C15's V30 stores only untrusted synthetic acquisition receipts and computes an immutable digest and atomic audit under ordinary database permissions. **A database superuser or owner who can disable triggers, restore an old backup or rewrite the database can roll back that entire history together.** A signed checkpoint only helps if its signing public key and latest checkpoint sequence/digest are independently provisioned and the checkpoint bytes are **actually retained outside PostgreSQL**.

D4-C16 introduces the required *offline verification primitive*, **not a real off-database storage provider**. There are no real witness public keys, independently custody-held high-water cursors, signing private keys, issuer roles, network fetches, hardware roots or production trust configuration. The only working signing keys are disposable synthetic Testcontainers fixtures.

## What the code does

- Add `StagedFidoMdsDetachedWitnessReader`: package-private, not a Spring Bean, endpoint, background agent or network client. The caller supplies **an independently pinned Ed25519 verification key**, an externally retained expected witness sequence and previous signed-witness hash, an external signed checkpoint, expected stream UUID and locally observed time. No private signing key is managed or generated by runtime code.
- A versioned, domain-separated, canonical US-ASCII Ed25519 transcript includes **V25 stream UUID, V30 acquisition record UUID, V26 source receipt UUID, V30 sequence, V30 database-owned acquisition SHA-256, V26 source SHA-256, V30 acquisition public-key pin, detached witness sequence, predecessor witness digest and asserted witness time**. The signature is exactly 64 bytes and witness public key fingerprint must match the separately supplied pinned key; witness and acquisition key fingerprints must be distinct.
- A **single PostgreSQL SELECT snapshot** reads the actual *latest* V30 receipt in the specific stream, its V26 source row, the two database-owned digests, acquisition key pin and matching V30 audit count. A valid detached signature is **not** accepted if the database tail has advanced, the whole tail was rolled back, the V26 receipt is missing/changed, a forged stream/record/source is substituted, an audit is missing, or the actual database SHA-256 differs.
- Strict external predecessor cursor check: witness sequence must equal an externally retained expected next sequence. The first witness requires a null predecessor; later witnesses require the exact externally retained SHA-256 of previous canonical signed-witness transcript+signature bytes. The verifier returns only `UntrustedDetachedWitnessMatch` and the digest suitable for **separately retained** next cursor. If the cursor or signing key is taken from the same untrusted database or caller, **this proves no external freshness or tamper resistance**.
- The witness's date is signed, but its temporal accuracy is NOT established. The method rejects assertions more than five minutes in the future relative to **caller-provided** local observed time; no externally trusted clock is integrated, and old archival signatures are not made invalid by an arbitrary short expiry.
- V30 can still store synthetic dummy acquisition signatures by direct SQL, deliberately. **Detached witness verification does not establish C14 Ed25519 acquisition signature, official CRL/MDS download, genuine TLS provenance, independent reviewer identities or trusted WebAuthn/CA.** It checks a signed *snapshot of database bytes*, nothing more.
