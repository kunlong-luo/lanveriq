# RD-2 — RustDesk 会话强制授权与防绕过验收契约

**2026-11-08 | 状态：方案审查与自动负向保护已建立；真正远程会话授权仍 BLOCKED，禁止上线。**

关联：[ADR-0010](adrs/0010-rustdesk-remote-control-integration.md) · [RD-0—RD-3 实施计划](rustdesk-integration-plan.md) · [源代码安全保护](../../deploy/rustdesk-synthetic/verify_rd2_release_boundary.py)

## 1. 基于真实证据确定阻塞点

截至 [实际 RustDesk OSS 安全测试](https://github.com/kunlong-luo/lanveriq/actions/runs/42492172171)，未修改的服务端 1.1.16 与两台未修改的客户端 1.5.1 已在隔离网络中完成注册、A→B 会合信令和合成字节中继。测试还证明错误服务器密钥会被拒绝，但**仅知道正确公开的服务器公钥、没有 Lanveriq 会话的人仍可将会合请求发往已注册设备**。该事实**不等于可以绕过 RustDesk 本地密码或被控端批准取得桌面控制**，但已经证明纯 OSS 会合服务器不是 Lanveriq 的集中式管理员权限执行点。

**不可接受的伪方案：**仅在 Next.js 隐藏按钮、Spring 返回“允许”、客户端隐藏设备 ID、Caddy 限制页面来源、向前端发放一次性 URL/令牌，均不能阻止用户用原版客户端绕过 Lanveriq 连接原有 `hbbs/hbbr`。

## 2. 官方 Pro 能力与不能直接推断的事项

| 能力 | 官方资料确认 | 尚需证明 |
| --- | --- | --- |
| Access Control | 官方文档定义为**连接准入**，支持用户、用户组、设备组及禁用用户/设备 | Lanveriq 管理员、组、设备授权与 Pro 身份的一致映射；外部原版客户端绕过拒绝 |
| 分组授权 | 用户组与设备组规则**可累计**，任一规则放行即可访问 | “只授一组”的安全假设是否被其他授权路径意外覆盖；去除所有相关继承 grant |
| 控制端身份 | 连接发起方的用户/组依据**实际登录用户**，非单凭控制端设备在控制台的归属 | 未登录原版客户端、注销后旧会话、身份映射混淆是否被真正禁止 |
| Control Role | 管理连接后的键鼠、剪贴板、文件、音频、终端等权限；有 **Not Logged** 和 **Default** 角色 | Not Logged 角色禁用**不等于**拒绝所有未登录的“连接准入”；需单独 L2 负例 |
| 中央管理 API | Pro 有 Web Console/API/管理 Token、用户/设备/权限管理 | 未看到可以直接承诺一次性**逐会话**强制授权和实时中断的已验证 API；不能假设 Token 管理接口就是会话发放接口 |
| 浏览器远控 | Web Client 自托管属于 Pro 产品能力 | 页面集成、License、CSP、同源认证、屏幕输入授权和服务端准入仍须真实验证 |

官方依据：[Access Control](https://rustdesk.com/docs/en/self-host/rustdesk-server-pro/permissions/) · [Control Role](https://rustdesk.com/docs/en/self-host/rustdesk-server-pro/control-role/) · [Web Console/API](https://rustdesk.com/docs/en/self-host/rustdesk-server-pro/console/) · [Pro 产品能力](https://rustdesk.com/docs/en/self-host/rustdesk-server-pro/)。

**版本约束（候选，非部署批准）：**官方 Access Control 文档要求设备组功能使用 RustDesk Client ≥1.3.8、Server Pro ≥1.5.0；官方 Control Role 文档要求被控端 RustDesk ≥1.4.5，Privacy Mode 另外要求 Pro ≥1.8.7 与被控客户端 ≥1.4.7。现有客户端 1.5.1 在版本号上满足上述客户端门槛，但尚未对任何 Pro 二进制做授权、漏洞、协议兼容和商业许可证验收。不得用“版本号满足”冒充已通过。

## 3. 推荐候选方案与接口边界

**优先进入验证的方案：**商用许可允许的 RustDesk Server Pro（或真正具备等价服务端执行能力的成熟平台），使用可核验的**连接前 Access Control** 而非仅依靠 Control Role。Lanveriq 仍是管理员和设备授权权威；RustDesk Pro 只能在确认身份绑定、同步撤权和旁路拒绝后承担数据面的准入执行，不得产生第二套独立且更宽松的管理员授权真相。

候选控制流程（设计，不是代码已实现）：

1. 管理员在 Lanveriq 控制台以受保护会话和当前数据库角色/组申请；目标是 UUIDv7 设备 ID，不是由浏览器任意提交的 RustDesk peer ID。
2. 服务端查数据库中的**当前有效设备→peer ID 绑定**，检查用户、组、设备在线/撤销、用途及组织级许可；必须有被控端明确批准策略。
3. **只有经双方验证且真实能够执行准入/中断的 Pro/其他数据面适配层**才允许继续。其可选的身份与权限同步功能不能替代实时可取消的单会话执行能力。
4. 数据面执行准入，客户端才开始握手；Spring 记录最小必要的请求、拒绝、批准、连接、终止审计，令牌/密码/密钥不进入 URL、HTML、日志或持久浏览器状态。
5. 管理员被禁用、设备被撤销、授权消失、用户取消、超时或服务端故障时，**正在传输的桌面会话也必须断开**；仅设置数据库记录为 stopped 或隐藏 UI 不通过。

**最小降级规则：**如果不能验证 Pro 对每一个会话状态迁移、即时撤权及外部原版客户端的拒绝，产品功能保持 **OFF**，不回退成开放 OSS 网络、共享常驻密码或假前端授权。若最终选用另一家产品，必须按同一门槛验收。

## 4. 可执行环境的 L2 防绕过用例矩阵

以下所有用例都必须用**未修改的官方客户端、真实服务器执行结果和独立于前端的审计证据**判断，不能只看 API JSON/UI 状态。每条结果初始化为 `NOT_RUN`，无证据不得写 PASS。

| ID | 测试操作（均为隔离合成环境） | 必须得到的结果 |
| --- | --- | --- |
| AUTH-01 | 未登录的官方客户端知道真实 peer ID 与服务器公钥，直接连接 | 连接准入拒绝，无桌面会话 |
| AUTH-02 | 已登录但仅有另一设备组权限 | 连接准入拒绝，跨组不可见 |
| AUTH-03 | 通过用户组或设备组任一**额外**授权路径尝试跨组 | 列出全部授权路径，撤净多路径后拒绝；不得误以为组规则是 AND |
| AUTH-04 | 账号已禁用，但旧客户端仍登录 | 新连接拒绝，当前活跃会话按撤权目标断开 |
| AUTH-05 | 被控设备禁用、撤销或 UUID↔peer 绑定已变更 | 旧 ID、旧绑定和旧凭证均不能准入 |
| AUTH-06 | 复制已签发给 A→B 的材料用于 A→C 或其他管理员 | 绑定错误被拒绝 |
| AUTH-07 | 重放、复用、超时后的单次会话凭据 | 强制拒绝；不得退化为有效永久密码 |
| AUTH-08 | 用户主动取消或终止；管理员权限正在变更 | 真实画面与输入停止，服务端可证实断连 |
| AUTH-09 | Pro/API 不可用、证书过期或权限查询超时 | Fail closed；不可缓存旧的“允许”无限续连 |
| AUTH-10 | 直接 TCP/UDP、原版客户端、经 hbbr 中继或可直连 P2P 的路径尝试旁路 UI | 各底层入口同等执行准入，不能只保护 Web 入口 |
| AUTH-11 | 被控端拒绝同意，或 OS 不允许控制键鼠 | 无输入控制，明确显示失败/拒绝 |
| AUTH-12 | 授权后真实发送屏幕帧并允许受限输入，再撤销 | 正向可用且撤销后传输停止；画面存在不能仅凭心跳推断 |
| AUTH-13 | 多管理员并发、重复点击、断线后重新连接 | 会话数、生命周期、审计一致；权限不得扩大 |
| AUTH-14 | 文件传输、剪贴板、终端、端口转发、录制未被批准 | **分别被实际拒绝**，不能因允许“看屏幕”自动放开 |
| AUTH-15 | 尝试从控制台获取 API token、密码、公钥或连接配置 | 仅公开不可避免的服务器公钥；不泄漏可长期复用的秘密或高权限管理 token |
| AUTH-16 | 在授权改变时重新评估 Not Logged / Default / 指定 Control Role | 连接准入与连接后权限两套规则都符合最小权限，不能混用 |

必须记录测试服务器与客户端确切版本、许可证范围、哈希、随机设备身份、关联服务端日志事件、原始测试断言、拒绝与断连时序；敏感身份/密码和会话载荷不得存入公开 CI 日志。实际保密素材及商业 Pro 二进制不得提交至 GitHub 公开仓库。

## 5. 当前自动保护与退出条件

- [RustDesk OSS synthetic CI](../../.github/workflows/rustdesk-server-synthetic.yml) 只验证官方未修改的 OSS/客户端及信令/中继行为；它并**不**证明上述 Pro/服务端授权用例通过。
- 新增 [RD-2 源码发布保护](../../deploy/rustdesk-synthetic/verify_rd2_release_boundary.py)：校验 Spring `lanveriq.remote.enabled: false` 是字面量且不可通过环境变量翻转；当前不存在激活的远控 Spring HTTP 映射、Next.js 远控路由或 Caddy RustDesk 端口；通过 Python 单元负例自动验证失败分支。**这是快速源代码回归保护，不是 Spring 运行时路由安全测试、网络准入证明或法律认可。**
- **禁止**在 AUTH-01～AUTH-16 必需门槛及许可/SBOM/安全审查完成前，把远控状态从 `BLOCKED` 更新为 `READY`。所需上游 Pro 商业测试环境必须明确许可/授权后再安排；当前没有该环境，也不尝试下载未授权软件。
- 在服务端强制执行方案尚不确定时，**不实现可发放凭据的远控 API 或可连接真实设备的按钮**；保持 Draft PR，不修改生产 `main`。
