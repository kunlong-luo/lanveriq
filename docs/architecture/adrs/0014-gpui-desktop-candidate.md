# ADR-0014 — GPUI native Rust desktop migration candidate

**Status: ACCEPTED FOR DEVELOPMENT (candidate only; cutover not approved) · Date: 2026-11-27 · v0.1 NOT RELEASE READY**

## Context

MVP-01–07 closed the owner-operated local data chain. MVP-08 Tauri frontend 42/42 passed; native jobs failed in the Ubuntu dependency audit, and the owner reported a separate GdkPixbuf startup panic. That evidence does not establish a comparative performance win or prove that Tauri's icon was the cause. The maintainer chose to evaluate a native Rust interface before expanding business workflows.

## Decision

- Select GPUI Kit exact 0.11.0 for an isolated nonrelease candidate, with its matched GPUI-pre 0.3.14 distribution. [Tagged release](https://github.com/longbridge/gpui-kit/releases/tag/v0.11.0) (2026-11-23, tag commit e97fe438129c5e4ccab504f2e6fafd9a4e396bba), [installation](https://gpui-kit.com/docs/installation/), [getting started](https://gpui-kit.com/docs/getting-started/). Use the Kit facade and styled components, no independently updated GPUI snapshot, GPUI Fast, optional speech, shell or WebView features. Source and code examples Apache-2.0; GPUI snapshot upstream notice also Apache-2.0 per documentation; no reuse of Zed application GPL code. Audit resolved licenses, assets, notices, SBOM and vulnerabilities before distribution.
- Preserve the one desktop product: temporary candidate in apps/desktop/gpui-candidate, freeze Tauri business expansion. Do not delete Tauri or its safety evidence until candidate has reviewed committed lock, native build, owner window acceptance, parity with existing readonly features and isolated package audit. The candidate now commits the exact successful CI Cargo.lock and its SHA-256; both CI jobs require the tracked lock and must not regenerate it. RustSec results and maintenance warnings are recorded in the task ledger; successful scanning is not license or release approval. No new package publication or installer.
- Within MVP-08, a manual, bounded, fixed-path OS identity probe may read only `/proc/self/status` (refuse root or invalid UID) and `/etc/os-release` (exact target metadata); no raw strings retained, no subprocess, generic path, file writes, background collection or network. Metadata never grants installation or runtime permission. The separate runtime metadata module may additionally query only the fixed preview package with `/usr/bin/dpkg-query` and fixed service with `/usr/bin/systemctl --system ... show` under `/usr/bin/timeout` (3s TERM, 1s KILL grace), cleared environment, bounded stdout, suppressed stderr and no shell or UI-supplied arguments, plus metadata of the fixed legacy leaf. Fresh non-root identity, manual refresh, background executor and stale-state clearance are mandatory. No install/update/remove/start/stop/enable, polling or authority. Missing or failed output is unknown, not absence. GPUI-specific preflight additionally reads only XDG_CURRENT_DESKTOP, XDG_SESSION_TYPE, WAYLAND_DISPLAY as a bounded, untrusted claim and uses the same fixed dpkg-query boundary for three COSMIC packages and five amd64 packages mapped from the reviewed seven direct ELF DT_NEEDED entries. CI must reject direct ELF drift rather than silently updating the list. No raw session values, package versions, socket paths, APT source reads/updates or display connection. All three observations on target can yield metadata_only, never GPU/ABI validation, physical L3, installation or runtime authority. Old Tauri ABI lists are not GPUI ABI evidence; indirect/dynamically loaded dependencies and actual window/driver tests remain required.
- Keep Agent independent. Shared Rust model/validated configuration may later be reused; all platform-specific service control and privilege brokers remain separately authorized. Linux Wayland and X11 first, Windows SCM/UAC and macOS launchd/OS authorization later; cross-platform framework support is not project acceptance.
- Preserve sole Next.js Web, Java/Spring/JPA/PostgreSQL, existing Rust Agent/SQLite/mTLS and all defaults. No additional service, network, credential, package or elevation interface.

## Alternatives and tradeoffs

Tauri offers established tooling and React reuse but a WebView and separate frontend stack; Iced and libcosmic are valid native options, libcosmic primarily targets COSMIC; Slint has a separate DSL and distribution review. Prefer GPUI Kit's ready-made components and one Rust code path for this trial. Pre-1.0 APIs, native driver/runtime dependencies, IME, scaling, accessibility and packaging are risks. Upstream Ubuntu development list includes WebKitGTK even though GPUI renders natively. Inspect actual resolved and linked libraries; do not assert their absence or improved memory/startup/size without measurement.

## Acceptance and supersession

A disposable Ubuntu X11 smoke may run the exact compiled candidate as a non-root process under private Xvfb/Openbox and D-Bus, with software-rendering prerequisites, temporary home/runtime, bounded subprocesses and cleanup. Assert mapped native window, nonuniform synthetic window pixels, resize and Ctrl+Q clean exit. This is not physical COSMIC/Wayland, GPU, IME, complete interaction/accessibility, package or release acceptance. No Agent installation or service mutation; do not archive candidate binaries or real desktop screenshots.

A CI-only GUI archive audit may strip a copy of the exact compiled ELF, reuse the existing read-only dpkg-shlibdeps and archive member helpers, and build a disposable `.deb` with only the distinct GPUI candidate GUI, launcher and nonrelease notice. The package is not installed, signed, uploaded or published; only static audit text and sizes/digest are retained. Exact archive members, root archive ownership (not root execution), modes, official direct ABI floors and extracted file digests must be checked. This does not prove complete indirect/dlopen/tool runtime dependencies, distributable license/copyright/assets/SBOM, production package size or installation readiness.

In disposable CI only, observe the exact spawned X11 child executable mappings after resize, bound `/proc/<child>/maps`, retain only allowlisted system shared-library paths and counts of unclassified file-backed executable mappings (not raw addresses, PID or user paths). Bind the snapshot to source and ELF digest; use existing Debian ownership and python-apt mandatory installed satisfier traversal for observed owners, direct ABI packages and fixed query-tool packages. Preserve missing ownership/copyright receipt counts; this is a single X11 observation and an overapproximation of installed mandatory packages, not complete runtime/dlopen/Wayland closure, SBOM or legal approval. No product process inspection or package installation.

A separate CI-only supply-chain job pins [cargo-cyclonedx 0.5.10](https://github.com/CycloneDX/cyclonedx-rust-cargo/releases/tag/cargo-cyclonedx-0.5.10), emits CycloneDX 1.6 for x86_64 Linux without changing the committed lock, reconciles package/version pairs against Cargo normal/build graph, and hashes actual registry license/notice material and GPUI resource candidates. Report missing material, graph differences and local product license as OPEN; distinguish normal vs build-only graph paths and retain nested notice candidates and package VCS/repository claims without substituting them for exact upstream provenance or package-level license evidence; do not infer embedded assets or legal permission from package metadata or file presence. Archive only BOM and metadata/hash evidence, not assets or executables. Fixed upstream manifest/commit/license blob evidence can be indexed in the task ledger without closing package-level missing material; match the exact version, preserve additional third-party notices and record inaccessible or unbound sources. Same-version downstream distribution copyright records can corroborate authorship and license terms, but never substitute for the locked registry contents, exact upstream binding or complete notice obligations. A declared SPDX branch, a short license header or upstream file presence is not full package provenance or redistribution clearance. No approved license allowlist, full binary/OS SBOM, redistribution notices or release authority is implied.

Retain all official shlibdeps diagnostics. Independently corroborate the exact previously observed libc6 usrmerge loader diversion pair with read-only registered diversion, canonical loader ownership/hash and ELF interpreter evidence, and check all five installed amd64 package versions against the computed direct floors using apt_pkg. Unknown or incomplete warning patterns fail the candidate archive audit. Do not alter diversions or suppress warnings; installed-state corroboration is not a full symbol/clean-system ABI or release approval.

For performance evidence only, build default locked Cargo Release in the same disposable runner as debug, apply the same noninstalling GUI archive audit, and alternate three launches per profile in the private X11 session. Record exact ELF SHA/bytes, allowlisted direct dependencies, archive bytes, Popen-to-positive-pixel-probe latency including polling, and single-child RSS/PSS one second after that probe; retain min/median/max and individual samples. No controlled cold cache, peak or whole-process-tree measurement, Tauri comparison or physical COSMIC/GPU inference. Release profile is not release approval.

Terminating the test children is not normal application close. Protocol submission is not pixel readback, physical COSMIC/GPU, IME, accessibility or independent L3 proof; no raw protocol trace retained or released.
