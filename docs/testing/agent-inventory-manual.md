# INV-01 — Rust local asset inventory adapter acceptance (V0.1)

**Status 2026-10-31:** Rust `inventory.rs` bounded DTO/normalizer plus `inventory_platform.rs` on-demand Windows/Linux adapter are staged with locked mature dependencies. The adapter is **not called** by the Agent binary, Tokio service loop, network transport, SQLx outbox or installer. CI runs synthetic unit tests, **not an actual machine inventory run**. No employee/device data collection is authorized.

## Architecture and reusable crates

- **`sysinfo =0.37.1`** with **only `system` and `disk`** features; not its process/user, component/GPU or network enumerators. Query CPU brand/architecture/core counts, total RAM and **local** volumes with no file listing. Mounted disk data is static asset inventory, not 60-second performance metrics.
- **`os_info =3.15.0`** detects distro/Windows version. OS family is limited to Linux or Windows; unknown fields stay null, not zero. Service-process environment is **not used** to guess a logged-in X11/Wayland desktop session.
- **`network-interface =2.0.5`** retrieves NIC addresses and optional MAC, indexes and network masks using OS APIs; numeric IPv4/IPv6 masks must be contiguous. Loopback interfaces are omitted. Interface keys are device-scoped, deterministic labels from SHA-256 of the OS-provided interface name, **not a canonical device UUID or authentication factor**.
- Stable complete snapshots are built by `InventorySnapshot::from_raw` from a **separately assigned** `device_id`, durable `snapshot_id` and SQLite-managed monotonic `inventory_revision`. The adapter does **not** generate those, does not persist snapshots, and does not upload. The complete snapshot is shaped for [server Flyway V8](server-inventory-manual.md).
- Every snapshot allows up to **32 distinct NICs**, **16 IPs per NIC**, **64 volumes**, **16 capability markers**, ≤128 KiB JSON, explicit missing-field states and no DNS queries. Multiple addresses per NIC are normalized/sorted; duplicate addresses do not cause fake extra NICs, conflicting metadata fails closed. Empty/unknown system data must remain null/unavailable, not invented.
- The whitelist has **no** username, home-file enumeration, running-process data, hardware serial/TPM, Wi-Fi SSID/BSSID, precise location, app/command history, camera/microphone, clipboard, screen content or recording. Linux user-session mount paths and Windows Users mount paths are excluded before producing inventory values.
- `Cargo.lock` is generated by the **official Cargo resolver** on an isolated GitHub Actions runner; the temporary one-time workflow with write permission was deleted. Normal CI continues to require `--locked` and Linux/Windows unit/Clippy checks.

## Mandatory isolated OS acceptance (NOT RUN)

On a consented **isolated synthetic test host**, **after organizational and security approvals**, confirm:

1. Linux (Pop!_OS 24.04 KDE/KWin): proper distro/kernel/CPU/RAM, two or more NICs, IPv4/IPv6 addresses, local mounted volumes. Verify the service account's permissions; desktop session remains unknown where the process cannot observe it. Check the actual session type independently; KWin does not prove Wayland.
2. Windows 11 x64: OS version/build, physical/logical cores, RAM bytes, Ethernet/Wi-Fi/VPN adapters, MAC normalization, alternate disk mounts; validate Windows SCM account access without administrator privileges.
3. Disconnect/reconnect, DHCP/MAC rotation and inventory refresh. Verify that the **server-created UUIDv7 device ID does not change**, unchanged content is not republished every heartbeat and the durable SQLite revision is monotonic across restarts.
4. Missing permissions, absent network addresses, removable/dismounted disks, external/personal mounts, huge NIC arrays and unavailable manufacturer/model result in explicit null/unavailable state, not fabricated success.
5. Verify neither a service invocation nor diagnostic logs reveal username, real MAC/IP in CI/public issues, serial/TPM, BSSID/SSID, process command lines or private file paths.
6. Only after actual PostgreSQL V8, approved device mTLS Caddy/Spring bridge, scoped Administrator read and secure SQLite inventory outbox are accepted, consider wiring `collect_local_inventory()` into **a bounded startup/24-hour/on-change opt-in scheduler**. Do not connect it to the existing 30-second heartbeat loop.

**Strict stop:** CI compilation and synthetic normalization tests do not authorize employee telemetry, network exposure, a production pilot, OS service installation or screen/activity capture. V0.2 audit and V0.3 recording remain separately gated.
