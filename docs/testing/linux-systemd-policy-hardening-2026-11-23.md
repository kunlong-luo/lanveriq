# A11-G05-LNX1 — Pop!_OS systemd offline security-gate hardening

**ACTIVE SOURCE CHANGE · 2026-11-23 · Linux-first · NO real Pop!_OS L3 · v0.1 NOT RELEASE READY**

## Risk and objective

Before this change, [verify-systemd-popos24.py](../../apps/agent/tools/linux/verify-systemd-popos24.py) used Python assert statements to enforce core idle, non-root service requirements (PrivateNetwork=yes, IPAddressDeny=any, DynamicUser=yes, non-privileged ExecStart and zero capabilities). The [Python language specification](https://docs.python.org/3/reference/simple_stmts.html#the-assert-statement) confirms these assertions are omitted from generated bytecode with -O. A permissive mutated unit could therefore print PASS despite lost restrictions if executed with python -O/PYTHONOPTIMIZE.

**Fix:** all requirements are now explicit SystemExit fail-closed validation, independent of optimization flags. The verifier checks the **exact set of allowed Unit/Service/Install directives and required values** instead of only checking a handful of known-bad keys. This rejects new unreviewed startup hooks (ExecStartPre, ExecCondition), alternative network permissions (IPAddressAllow), identity/environment override (User, EnvironmentFile), host or namespace escapes (ReadWritePaths, JoinsNamespaceOf), and any weakened service sandbox. Duplicate directives, unexpected/missing sections, default-section inheritance, missing unit and incorrect command/condition/restart mode all fail, including under -O.

## Tests and scope

- Source: [static verifier](../../apps/agent/tools/linux/verify-systemd-popos24.py) — no systemctl or runtime changes.
- Synthetic negatives: [Python subprocess mutation tests](../../apps/agent/tools/linux/test_verify_systemd_popos24.py), normal and -O interpreter; 16 test methods, including multiple sandbox directive mutations.
- [Ubuntu24 synthetic custody workflow](../../.github/workflows/agent-linux-popos24-custody.yml) now executes this negative suite before validating the stock unit, calling systemd-analyze on a non-installed temporary copy, building offline CSR helper and executing isolated transient DynamicUser credential custody tests. It is NOT actual Pop!_OS or COSMIC.
- No changes to the installed service template, binary, networking, private keys, Agent scheduler, remote desktop or production feature flags. This fix does not justify starting the service.

**Limits:** verifies only the committed **template file**. It cannot detect host-specific /etc/systemd/system/... drop-ins, runtime transient properties, renamed installed units or admin overrides. A later approved **real Pop!_OS 24.04 L3** must inspect systemctl cat and systemctl show **effective** policy on an authorized disposable device, verify that the service remains inactive until approval, test non-root key custody/reboot persistence and compare with actual local consent rules. No actual System76 hardware, live network, real TLS/PKI, platform user session, cryptographic key erasure or physical integration was tested here. G-05 remains OPEN.

**Evidence discipline:** record exact SHA and Ubuntu CI run link only after actual completion. Previous C18i/C18f CI cannot be counted as tests of this source change.
